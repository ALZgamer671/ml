## 🧩 1. Несбалансированные классы

**Ситуация:** класс «покупка» — 2%, класс «нет покупки» — 98%. Обучение на accuracy «выгодно» всегда предсказывать мажоритарный класс.

### Проблема
- Accuracy на несбалансированных данных **врёт**: 98% accuracy, но полезной модели нет.
- Модель не видит миноритарный класс, градиенты «забиваются» мажоритарным.

### Решения
| Подход | Механика | Когда работает |
|---|---|---|
| **Взвешивание классов** | `class_weight='balanced'`, веса обратно пропорциональны частоте | почти всегда, быстро |
| **Ресемплинг** | oversampling миноритарного (SMOTE), undersampling мажоритарного | при нехватке данных |
| **Смена метрики** | Precision / Recall / F1 / PR-AUC вместо accuracy | оценка честнее |
| **Смена порога** | threshold ≠ 0.5, подбираем по PR-кривой | когда нужен конкретный баланс |
| **Аномали-детект вид** | задача как поиск выбросов (Isolation Forest, One-Class SVM) | если класс по-настоящему редкий |

### Главное запомнить
Чем важна **PR-AUC** на дисбалансе: ROC-AUC почти не меняется при сдвиге соотношения классов, а PR-AUC — меняется (Precision напрямую зависит от доли положительных). Выбор порога — это осознанный компромисс precision↔recall, а не святая константа 0.5.

## 🧹 2. Пропуски в данных и выбросы

### Пропуски (NaN)
1. Понять **механизм** пропусков: MCAR (случайно), MAR (зависит от других признаков), MNAR (зависит от самого значения) — от этого зависит лечение.
2. Стратегии: удалить (если мало), заменить средним/медианой (просто, работает, но занижает дисперсию), модой для категорий, **предсказать пропущенный признак моделью** (KNN-импьютация), отдельный бинарный флаг «было пропущено».
3. Для деревьев пропуски не так страшны — CatBoost обрабатывает их сам (считается одним из его плюсов).

### Выбросы
- Делятся на: ошибки данных (удалять/чинить) и истинные экстремумы (признак!).
- Методы: IQR (вне $\pm 1.5 \cdot IQR$), z-score, визуально на boxplot.
- Влияние: MSE сильно реагирует на выбросы (квадрат), MAE устойчивее, Huber — компромисс. Это уже из твоей лекции 2.

### Главное запомнить
- Для линейных моделей — нормализация **обязательна**, для деревьев — не важна.
- Порядок: сначала чистим/импьютим, потом кодируем/масштабируем, потом обучаем.

## 🎛️ 3. Подбор гиперпараметров

### GridSearch vs Random Search vs Bayesian (Optuna)
| Метод | Идея | Плюс |
|---|---|---|
| GridSearch | перебор всех комбинаций решётки | полно, но дорого |
| Random Search | случайные точки | при большом числе гиперпараметров выгоднее сетки («не все гиперпараметры одинаково важны») |
| **Optuna** (bayesian, TPE) | умный выбор следующей точки | 🔥 стандарт индустрии, на русском документация |

### Пример Optuna для бустинга
```python
def objective(trial):
    params = {
        'n_estimators': trial.suggest_int('n_estimators', 100, 1000),
        'learning_rate': trial.suggest_float('learning_rate', 0.01, 0.3, log=True),
        'max_depth': trial.suggest_int('max_depth', 3, 10),
    }
    model = LGBMClassifier(**params)
    return cross_val_score(model, X, y, cv=3, scoring='roc_auc').mean()

study = optuna.create_study(direction='maximize')
study.optimize(objective, n_trials=100)
```

### Главное запомнить
- Гиперпараметры подбираются по **валидации/CV**, а не по тесту — иначе ты «подгоняешь» тест.
- Кросс-валидация на временных рядах: **TimeSeriesSplit**, нельзя перемешивать прошлое с будущим (утечка будущего).

## 🧬 4. Утечка данных (data leakage) — критично для собеса

**Утечка** — когда информация из теста/будущего «просочилась» в обучение. Модель идеальна на кросс-валидации и проваливается в бою.

### Классические источники утечки
1. **Масштабирование до split:** `fit_transform` на всех данных (включая тест) → шкалы подтянуты тестом. Правильно: `fit` только на train, `transform` на тесте/валидации.
2. **Target encoding** с таргетом, включая тестовые строки → модель «видит» ответ.
3. **Утечка во времени:** в рядах — признаки из будущего (например, средняя цена за неделю *включая* день-предсказание).
4. **Дубликаты:** одинаковые строки в train и test → модель просто запоминает.

### Главное запомнить
Правило: **никакая информация из теста не участвует в обучении ни в каком виде**, включая нормализацию, encoding, подбор гиперпараметров и early stopping. Для тайм-серий — строго по времени, `TimeSeriesSplit`.

## 📐 5. Разложение ошибки: bias–variance (глубже, чем в лекции 8)

### Идея
Ошибка модели = **шум** (неустраним) + **смещение (bias)** + **разброс (variance)**.
$$E[(y - \hat f(x))^2] = \sigma^2 + \mathrm{Bias}^2[\hat f(x)] + \mathrm{Var}[\hat f(x)]$$

### Интуиция
- **Высокий bias** = модель слишком простая, не улавливает закономерность (недообучение). Линейная модель на зашумлённых данных.
- **Высокая variance** = модель слишком сложная, реагирует на шум конкретной выборки (переобучение). Глубокое дерево без ограничений.
- С ростом сложности модели bias падает, variance растёт — есть оптимум.

### Борьба
| С bias | С variance |
|---|---|
| больше признаков / сложнее модель | регуляризация (L1/L2, dropout) |
| меньше данных-шума | больше данных |
| более гибкое семейство | ансамбли (усреднение снижает variance) |
| | ограничение сложности (глубина дерева, min_samples) |

## 🎯 6. Калибровка вероятностей (частая тема у практиков)

Проблема: бустинг выдаёт «псевдовероятности», которые могут быть смещены. Нам нужны настоящие вероятности для бизнеса (например, «90% шанс вернуть долг»).

- **Platt scaling:** логистическая регрессия на выход scores модели.
- **Isotonic regression** (изотоническая): непараметрическая калибровка, может испортитьранжирование.
- Метрика калибровки: **Expected Calibration Error (ECE)** — среднее расхождение между предсказанной и фактической частотой события.

### Главное запомнить
Калибровка важна там, где:** вероятности потребляются напрямую**, а не только порядок (ранжирование). Для поиска/ранжирования важнее AUC, для расчёта риска — калибровка.

## 📊 7. Feature importance и интерпретация

Три подхода к важности признаков, и почему они разные:
1. **Gain / feature_importance_** (в XGBoost/LGBM) — сколько раз признак использован + прирост качества. Быстро, но смещено к числовым/высококардинальным признакам.
2. **Permutation importance** — портим признак значениями и смотрим падение метрики. Честнее, дороже.
3. **SHAP** — вклад каждого признака в каждое предсказание (игровое значение). 🔥 стандарт для объяснений, красивые графики, есть русскоязычные гайды.

### Главное запомнить
- Высокая важность ≠ признак «правильный»: он может быть коррелирован с другим важным.
- Для деревьев можно построить **ATSE-интерпретацию** пути решения — объяснить конкретное предсказание (почему отказали кредитной карте 42-летнему Ивану).

## 📦 8. Практические пайплайны (sklearn Pipeline+ColumnTransformer)

Когда признаков разных типов много — весь препроцессинг собирается в один объект:
```python
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder

prep = ColumnTransformer([
    ('num', StandardScaler(), num_cols),
    ('cat', OneHotEncoder(), cat_cols),
])
pipe = Pipeline([('prep', prep), ('model', RandomForestClassifier())])
# кросс-валидация проезжает по всему пайплайну — нет утечки
cross_val_score(pipe, X, y, cv=5)
```

### Главное запомнить
Пайплайн решает проблему утечки автоматически (пункт 4): все `fit`/`transform` происходят внутри каждого фолда CV отдельно. На собеседовании это сильный плюс.

|---|---|
| У меня 2% положительного класса, что делать? | Взвешенные классы → метрика PR-AUC → подбор порога → при желании ресемплинг/SMOTE |

| Bias vs variance? | Ошибка = шум + bias² + variance; сложнее модель → bias падает, variance растёт; компромисс |
| Модель выдаёт «вероятности», им можно верить? | Нужно калибровать (Platt/isotonic), проверять ECE |
| Как понять, какой признак важен? | Gain / permutation importance / SHAP, у каждого свои смещения |
